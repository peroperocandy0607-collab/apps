## 1. 目的

WordPress の指定カテゴリー（子カテゴリー含む）の**投稿ページ**に、バナーを自動で表示する。

- **記事上**（本文の先頭）：「わたし、天使なの？」と「僕の過去世」を、記事IDの偶数・奇数で交互に1枚表示
- **記事下**（本文の最後＝まとめの下）：「霊性開花」を1枚表示
- 対象外カテゴリーの記事・トップページ・一覧・フィードには表示しない

## 2. 使うもの

プラグイン `niji-office-banners.zip`（完成品。**コードの修正は不要**）

- 入手先：GitHub `peroperocandy0607-collab/apps`、ブランチ `claude/angel-series-article-rewrite-ykr9jb` のリポジトリ直下 `niji-office-banners.zip`
- 中身：`niji-office-banners/niji-office-banners.php` と `images/` 内の最適化済みWebP 3枚（1400×560px・各61〜105KB）
- 有効化すると、画像3枚が自動で**メディアライブラリにアップロード**され（altつき）、記事では srcset 付きで表示される
- 設定は `wp_options` の `niji_ob_settings` に保存。画像の添付ファイルIDは `niji_ob_attachments` に保存

## 3. 作業前の必須事項

1. **バックアップ**を取る（データベースと `wp-content`）。WP-CLI なら `wp db export backup-before-banner.sql`
2. 旧版が入っていないか確認：`wp-content/mu-plugins/niji-banners.php` があれば**削除**する（旧版には、対象外の記事で致命的エラーを起こす不具合がある）
3. 子テーマや `functions.php` は**編集しない**。このプラグインだけで完結する

## 4-A. 作業手順（SSH + WP-CLI の場合）

```bash
# 1) インストールと有効化（有効化の時点で画像がメディアライブラリへ登録される）
wp plugin install /path/to/niji-office-banners.zip --activate

# 2) 対象カテゴリーの term_id を確認
wp term list category --fields=term_id,name,slug,parent,count

# 3) 設定を保存（categories は手順2で確認した「親カテゴリー」の term_id。子カテゴリーは自動で含まれる）
wp option update niji_ob_settings --format=json '{
  "categories": [親カテゴリーID1, 親カテゴリーID2],
  "top_mode": "alternate",
  "urls": {
    "tenshi": "天使バナーのリンク先URL",
    "kakoze": "過去世バナーのリンク先URL",
    "reisei": "霊性開花バナーのリンク先URL"
  }
}'
# top_mode は "alternate"（交互） / "tenshi" / "kakoze" のいずれか

# 4) 画像がメディアに3件登録されたか確認（3件の添付IDが出ればOK）
wp option get niji_ob_attachments --format=json

# 5) キャッシュ系プラグインがあればキャッシュを削除
wp cache flush
```

## 4-B. 作業手順（管理画面の場合）

1. 「プラグイン」→「新規追加」→「プラグインのアップロード」→ zip を選択 →「今すぐインストール」→「プラグインを有効化」
2. 「設定」→「占い記事バナー」を開く
3. ①で対象の**親カテゴリー**にチェックを入れる
4. ②の3つの欄にリンク先URLを入力する
5. ③は「交互に表示」のまま →「保存する」
6. キャッシュ系プラグインがあればキャッシュを削除

## 5. 完了確認（すべて満たすこと）

- [ ] メディアライブラリに `banner-tenshi.webp`、`banner-kakoze.webp`、`banner-reisei.webp` が**各1件ずつ**ある（重複していない）
- [ ] 対象カテゴリーの記事を**2本以上**開き、記事上に天使または過去世、本文の最後に霊性開花が出ている（記事によって上のバナーが入れ替わる）
- [ ] 子カテゴリーの記事（例：「1月生まれ」など）にも表示されている
- [ ] **対象外カテゴリーの記事**を1本開き、バナーが出ず、エラーもなく表示される
- [ ] トップページとカテゴリー一覧ページにバナーが出ていない
- [ ] 各バナーをクリックすると、指定したURLが開く
- [ ] スマホ幅（390px）で横にはみ出していない
- [ ] `wp-content/debug.log` に `niji` を含む Fatal / Warning が出ていない（WP_DEBUG が有効な場合）

## 6. 例外対応

| 症状 | 対処 |
|---|---|
| バナーが出ない | ① 設定でカテゴリーにチェックがあるか ② そのバナーのURLが空になっていないか（**空だと出ない仕様**） ③ キャッシュを削除 |
| 記事上だけ出ない／下だけ出ない | 該当バナーのURL欄が空。入力して保存 |
| 特定の記事だけ出したくない | その記事のカスタムフィールドに、名前 `niji_banner_off`、値 `1` を追加 |
| 画像がメディアから消えた | 管理画面を開けば自動で再登録される |
| 目次プラグインなどと位置がぶつかる | 本文フィルターの優先度20で挿入している。位置の変更が必要なら、**コードを変える前に依頼者へ相談** |
| サイトが表示されなくなった | すぐにプラグインを無効化：`wp plugin deactivate niji-office-banners`（管理画面に入れない場合は、`wp-content/plugins/niji-office-banners` フォルダの名前を変える） |

## 7. やってはいけないこと

- テーマ・子テーマ・`functions.php` の編集
- 過去記事の本文にバナーのHTMLを直接書き込むこと（一括置換を含む）
- 画像の差し替え・再圧縮（最適化済み）
- 確認の取れていないリンク先URLを入れること（空欄のままなら表示されないので安全）

## 8. 元に戻す方法

- 一時停止：プラグインを「無効化」するだけで、全記事から即座に消える（記事本文は一切変更していない）
- 完全削除：無効化 → 「削除」。設定を消す場合は `wp option delete niji_ob_settings niji_ob_attachments`。メディアの画像3枚は必要に応じて手動で削除
